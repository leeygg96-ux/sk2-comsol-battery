# Architecture decision log

## D-001 — COMSOL 모듈은 단일 저장소로 관리

**결정:** 열적 남용과 충·방전은 `sk2-comsol-battery` 안의 별도 디렉터리로 둔다.

**이유:** 셀 형상, 좌표계, 단위 규약과 향후 일부 공통 코드를 공유할 가능성이 있으나, 현재의 물리 모델과 개발 주기는 다르다.

## D-002 — 논문은 별도 저장소로 분리

**결정:** 논문 원고, 참고문헌, 투고 양식은 `sk2-paper`에서 관리한다.

**이유:** 논문 편집 이력과 시뮬레이션 코드 이력을 분리하고, 논문이 검증된 모델 태그를 명시적으로 참조하게 한다.

## D-003 — Java를 모델 정의의 원본으로 사용

**결정:** 재생성 가능한 Java는 Git에 저장하고, 생성된 MPH는 기본적으로 무시한다.

**이유:** MPH는 바이너리라 diff 검토가 어렵고 용량이 커질 수 있다. 검증된 MPH 보존이 반드시 필요할 때만 Git LFS 또는 외부 릴리스 산출물을 검토한다.

## D-004 — 모듈별 장기 브랜치 대신 짧은 작업 브랜치와 worktree 사용

**결정:** `thermal-abuse`와 `charge-discharge`라는 장기 브랜치를 유지하지 않는다. `ta/<task>`, `cd/<task>` 단기 브랜치와 별도 worktree를 사용한다.

**이유:** 장기 브랜치의 이력 분기와 대규모 병합을 피하면서 작업 폴더와 Codex 문맥은 분리할 수 있다.

## D-005 — 공통화는 중복 확인 후 수행

**결정:** 처음부터 현재 열적 남용 Java 파일을 공통 클래스로 분해하지 않는다.

**이유:** 충·방전 모델의 실제 요구사항이 확인되기 전에 추상화하면 잘못된 결합이 생길 수 있다.
